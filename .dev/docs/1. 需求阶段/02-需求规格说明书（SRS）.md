## 1. 引言

### 1.1 编写目的

> 本文档旨在定义薄荷商城后台系统的功能与性能需求，为系统的设计、开发、测试和验收提供依据。预期读者包括项目经理、开发人员、测试人员、用户代表及维护人员。

### 1.2 适用范围

> 本文档适用于薄荷商城后台系统 V1.0 版本的开发与验收，描述该系统应实现的功能及约束。

## 2. 总体描述

### 2.1 产品前景

> 薄荷商城后台系统是一个独立的 B2C 电子商务平台，为用户提供在线购物、订单管理等服务，同时为商家提供商品与库存管理、订单处理能力，并为平台管理员提供全平台监管、审核与统计功能。

### 2.2 产品功能与用户特征

**主要功能概要：**

- 用户注册与登录、密码管理、Token 刷新
- 商品浏览、搜索与详情查看
- 购物车管理（增删改查、勾选、结算）
- 订单全生命周期管理（创建、支付、发货、收货、退款/售后）
- 支付与资金管理（多端支付、提现、对账）
- 消息与通知（站内信、状态变更推送、公告）
- 库存管理（入库、调整、预警、盘点）
- 平台审核与监管（商家资质审核、商品审核、退款仲裁）

**用户角色：**

| 角色 | 职责与特征 |
| ---- | ---------- |
| 用户（USER） | 浏览商品、下单、管理购物车与订单、接收消息通知，需简洁易用界面 |
| 商家（MERCHANT） | 管理商品信息与库存、处理订单与发货、管理资金与提现、接收平台通知，需批量操作功能 |
| 平台管理员（PLATFORM） | 审核商家资质与商品、监管全平台订单与资金、管理角色权限与推送公告、处理纠纷仲裁，需审计日志 |

### 2.3 运行环境

- **客户端：** 支持 Chrome、Edge、Safari 近 2 年版本
- **服务端：** Linux CentOS 7+，Nginx 1.20，Java 17，MySQL 8.0+，Redis 7.2
- **移动端：** Android 近 2 年版本，iOS 近 2 年版本
- **网络：** 需互联网连接，最低带宽 2Mbps

### 2.4 设计与实现约束

- 后端必须使用 Java 语言（JDK 17），基于 Spring Boot 框架
- 数据库采用 MySQL，ORM 框架采用 MyBatis-Plus
- 需符合《个人信息保护法》及 GB/T 35273 要求
- 支付接入需遵循支付宝开放平台商家接入文档
- 代码需符合《阿里巴巴开发规约》黄山版
- API 需携带版本号，保持向后兼容

### 2.5 假设与依赖

- 假设用户都具备基本的计算机操作能力
- 依赖第三方支付网关（支付宝）接口按时提供且文档完整
- 依赖短信/邮件服务供应商稳定运行
- 假设硬件资源将在项目启动后两周内部署到位

## 3. 具体需求

### 3.1 功能需求

#### 3.1.1 用例/用户故事

**用例 UC-01：用户注册**
- **参与者：** 游客
- **前置条件：** 用户处于未登录状态
- **基本流：**
  1. 用户访问注册页面
  2. 系统显示注册表单（用户名、密码、邮箱、手机号）
  3. 用户填写信息并提交
  4. 系统验证信息合法性，成功则发送验证邮件/短信
  5. 用户完成验证，注册成功
- **后置条件：** 用户注册成功，可登录系统

**用例 UC-02：用户登录**
- **参与者：** 用户
- **前置条件：** 用户已注册且处于未登录状态
- **基本流：**
  1. 用户访问登录页面
  2. 输入用户名/邮箱/手机号 + 密码
  3. 系统验证凭证，返回授权 Token
  4. 用户登录成功，进入系统首页
- **后置条件：** 用户获得有效 Token，可访问受保护资源

**用例 UC-03：商家登录**
- **参与者：** 商家
- **前置条件：** 商家已注册且通过资质审核
- **基本流：**
  1. 商家访问商家端登录页面
  2. 输入商家账号 + 密码
  3. 系统验证凭证与资质状态，返回授权 Token
  4. 商家登录成功，进入商家管理后台
- **后置条件：** 商家获得有效 Token，可访问商家端功能

**用例 UC-04：管理员登录**
- **参与者：** 平台管理员
- **前置条件：** 管理员账号已由超级管理员创建
- **基本流：**
  1. 管理员访问平台管理端登录页面
  2. 输入管理员账号 + 密码
  3. 系统验证凭证与角色权限，返回授权 Token
  4. 管理员登录成功，进入平台管理后台
- **后置条件：** 管理员获得有效 Token，可访问平台管理功能

| P-2 | 跨商家库存调拨 | PLATFORM-STOCK-0002 | PLATFORM |
| P-3 | 库存盘点任务下发与回收 | PLATFORM-STOCK-0003 | PLATFORM |
| P-4 | 异常库存核查与纠正 | PLATFORM-STOCK-0004 | PLATFORM |
| P-5 | 低周转/滞销商品库存预警统一下发 | PLATFORM-STOCK-0005 | PLATFORM |

### 3.2 非功能需求

#### 3.2.1 性能需求

- 核心交易接口 P99 响应时间 < 500ms
- 商品列表 QPS ≥ 1000
- 下单写 QPS ≥ 200
- 页面首屏加载 P95 < 2s

#### 3.2.2 安全性需求

- 需防范 OWASP Top 10 安全风险
- 采用 RBAC 权限控制，防止越权访问
- 敏感数据加密存储与传输
- 关键接口支持幂等防重
- 需符合《个人信息保护法》合规要求
- 操作日志需记录用户关键行为，日志保留不少于 6 个月

#### 3.2.3 可用性需求

- 系统可用性应达到 99.9%（按月度计算）
- 支持灰度发布，降低上线风险
- 具备回滚能力，异常版本可在 10 分钟内回退
- 关键依赖需具备主备切换与降级方案

#### 3.2.4 可靠性需求

- 系统在宕机后应能在 10 分钟内自动或手动恢复
- 交易数据需保证不丢失，支持事务回滚
- 支付订单数据需保证最终一致性

#### 3.2.5 可维护性需求

- 代码需符合《阿里巴巴开发规约》黄山版
- 核心模块需提供单元测试，覆盖率不低于 80%
- 关键业务链路需具备可观测埋点
- 配置需外置，支持动态配置更新

#### 3.2.6 可移植性需求

- 后端服务需能迁移至主流 Linux 发行版，无代码修改
- 前端需支持 Chrome、Edge、Safari 近 2 年版本
- 移动端需支持 iOS、Android 近 2 年版本
- API 需携带版本号，确保兼容性

### 3.3 接口需求

#### 3.3.1 用户界面

- 采用响应式设计，适配 PC 与移动端
- 用户端、商家端、平台管理端各自独立界面风格
- 所有删除操作均需弹出二次确认
- 列表页需支持分页与条件筛选

#### 3.3.2 硬件接口

- 本系统为纯软件应用，无直接硬件接口需求

#### 3.3.3 软件接口

- **支付网关接口：** 调用支付宝开放平台 API，采用 RESTful，JSON 格式
- **短信服务接口：** 通过 HTTP 方式调用短信平台
- **数据导出：** 支持导出为 Excel (.xlsx) 格式，供财务系统使用

#### 3.3.4 通信接口

- 前后端通信采用 HTTPS，API 遵循 RESTful 设计
- WebSocket 用于实时消息推送
- 与第三方系统间采用 SFTP 交换文件

### 3.4 数据需求

- 用户信息表需包含字段：用户ID、用户名、密码哈希、邮箱、手机、注册时间、角色类型等
- 商品表需包含字段：商品ID（SPU/SKU）、名称、描述、图片、价格、库存、商家ID、审核状态等
- 订单表预计每年增长 50 万条，历史数据需在线保留 3 年，超过后可归档
- 支付流水表需记录每笔交易的完整生命周期
- 库存变动表需记录每次入库、出库、调整的流水明细
- 需设计合理的索引以优化查询性能
