## 1. 优先级定义

| 优先级 | 含义 | 说明 |
|--------|------|------|
| P0 | 核心必备 | 没有它系统无法上线，阻塞后续开发 |
| P1 | 重要功能 | 首个可用版本（MVP）必须包含 |
| P2 | 一般功能 | 提升体验或辅助流程，可延后 |
| P3 | 锦上添花 | 非必须，有资源时再做 |

## 2. 状态标识

| 状态 | 含义 |
|------|------|
| TODO | 待开发 |
| DEV | 开发中 |
| TEST | 测试中 |
| DONE | 已完成 |
| HOLD | 暂缓 |

> 首期所有功能状态为「待开发」、负责人为「待分配」，进入开发阶段后按迭代更新。

## 5. 使用说明（Java 工程师视角）

1. **与代码映射**
   - 功能编号可作为 Git 分支命名的一部分，如 `feat/user-auth-0001-login`。
   - 接口路径、Service 方法命名可体现功能归属，方便追溯。

2. **依赖管理**
   - 明确依赖关系，避免开发阻塞。后端接口开发顺序应遵循从 P0 核心到 P1 外延的原则。
   - 对跨模块功能，可先定义好 API 契约（如 OpenAPI/Swagger），让前端和下游可以并行。

3. **工时估算**
   - 初期可采用人天粗估，随着技术方案确定再拆分子任务。
   - 建议预留联调与回归测试时间，P0 任务应尽早进入测试。

4. **与研发工具联动**
   - 可直接将本表导入 JIRA/禅道，或用 CSV 格式同步。
   - 使用标签（如 P0, high-risk）生成燃尽图或风险报告。

5. **维护策略**
   - 每次迭代后更新状态，删除已完成项或移至"已交付"附录。
   - 评审会时统一检查优先级是否因需求变化而调整。
