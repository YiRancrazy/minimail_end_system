## 文档目的

> 定义模块间/系统间内部接口（区别于对外 API）的协议、数据结构与契约，确保模块协作边界清晰、依赖可控。

## 适用范围

- **适用对象**：架构师、后端开发、测试
- **适用场景**：模块拆分、依赖设计、集成测试
- **不适用范围**：对外 HTTP API（见 [API 设计文档](02-API设计文档.md)）

## 详细内容

### 1. 接口分类

| 类别 | 协议 | 适用场景 | 工具 |
|------|------|----------|------|
| OpenFeign 同步调用 | HTTP/REST | 跨服务同步业务调用 | 接口包 + 实现包分离，`@FeignClient` |
| RocketMQ 异步消息 | MQ | 跨服务状态广播、削峰、解耦 | 事务消息 + 死信队列 |
| 内部方法调用 | JVM 内 | 同进程模块协作 | 直接方法调用 |
| Redis 缓存 | TCP | 高频读、临时数据、分布式锁 | key 命名规范 |
| Elasticsearch | HTTP | 商品搜索索引同步 | 异步 MQ 投递 |

> **禁止**共享数据库跨服务直连；所有数据交互走 OpenFeign 或 MQ。

### 2. OpenFeign 内部契约约定

业务服务间的内部调用走 OpenFeign，对外暴露在 K8s 集群内，**不进入网关**（避免被外网扫描）。约定：

- 内部接口路径：`/internal/<service>/...`；
- 内部接口必须同样使用 OpenAPI 注释；
- 入口使用 `X-Internal-Token` 鉴权（短期 JWT，scope 严格最小）；
- 内部调用不暴露给前端文档，仅运维可见；

示例：

```java
import com.yirancrazy.minimall.api.stock.StockReserveRequest;
import com.yirancrazy.minimall.api.stock.StockReserveResponse;
import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;

@FeignClient(name = "stock-service", path = "/internal/stock")
public interface StockInternalClient {
    @PostMapping("/reserve")
    StockReserveResponse reserve(@RequestBody StockReserveRequest req);
}
```

### 3. 服务间同步契约清单

| 调用方 → 被调方 | 接口路径 | 用途 | 备注 |
|---|---|---|---|
| `gateway` → `auth-service` | `POST /internal/auth/verify` | 网关验签后回填角色 | internal 路径不暴露网关外 |
| `cart-service` → `goods-service` | `POST /internal/goods/sku/snapshot` | 结算时取商品快照 | 含 SPU/SKU/价格/库存快照，避免下单后改价 |
| `order-service` → `stock-service` | `POST /internal/stock/reserve` | 锁定库存（Seata AT 全局事务） | |
| `order-service` → `pay-service` | `POST /internal/pay/create` | 创建支付流水 | |
| `pay-service` → `order-service` | `POST /internal/order/paid` / `/cancel` | 支付成功/失败通知 | MQ + RPC 双通道，MQ 为主 |
| `order-service` → `notify-service` | `POST /internal/notify/send` | 触发站内信 + WS 推送 | 事务消息 |

### 4. 服务间异步事件契约

| Topic | 生产者 | 消费者 | 事件体关键字段 | 用途 |
|---|---|---|---|---|
| `ORDER_STATUS_CHANGED` | `order-service` | `notify-service`, `merchant-service` | `orderNo`, `oldStatus`, `newStatus`, `userId` | 订单状态变更通知 |
| `REFUND_REQUESTED` | `order-service` | `merchant-service`, `notify-service` | `refundNo`, `orderNo`, `reason` | 退款申请通知 |
| `REFUND_RESULT` | `pay-service` | `order-service`, `notify-service` | `refundNo`, `success`, `amount` | 退款结果通知 |
| `PAY_CALLBACK` | `pay-service` | `order-service` | `paymentNo`, `orderNo`, `tradeNo`, `success` | 支付宝异步回调转发 |
| `GOODS_CHANGED` | `goods-service` | ES 索引同步 | `spuId`, `action ∈ {UPSERT, OFF_SHELF}` | 商品索引同步 |
| `STOCK_WARNING` | `stock-service` | `merchant-service`, `notify-service` | `skuId`, `currentQty`, `threshold` | 库存预警通知 |

MQ 约定：
- 生产者使用 **事务消息** 保证本地事务与消息投递的原子性；
- 消费者自重试 3 次（间隔 1s/5s/30s），仍失败入死信队列，人工介入；
- 每条消息必须携带 `traceId`，与调用链关联。

### 5. 接口命名规范

- 包名：`com.yirancrazy.minimall.api.<模块>`
- 接口名：`I<模块名>Service`（Java 习惯）或 `<模块名>Facade`
- 方法名：动词 + 名词，如 `getUserById`、`placeOrder`
- 异常：业务异常使用 `BizException` + 错误码

### 6. 接口契约要素

每个接口**必须**包含以下信息：

```
1. 接口名称
2. 调用方与被调用方
3. 输入参数（含类型、约束、必填）
4. 输出参数（含类型、字段说明）
5. 异常处理（业务异常 / 系统异常）
6. 幂等性保证
7. 性能要求（SLA）
8. 监控埋点要求
9. 版本与兼容性策略
10. 示例
```

### 7. 接口示例

#### 7.1 stock-service.reserve（同步 OpenFeign）

```text
接口：IStockService.reserve
调用方：order-service
被调用方：stock-service
版本：V1
路径：POST /internal/stock/reserve

输入：
  items: List<StockReserveItem>  // 必填，≥ 1
    skuId: Long       // SKU 主键
    quantity: Integer  // > 0

输出：
  StockReserveResponse {
    success: Boolean
    reserveNo: String     // 库存预留单号
    failedItems: List<FailedItem>  // 预留失败的 SKU
  }

异常：
  BizException(STOCK_NOT_ENOUGH, "库存不足")
  BizException(STOCK_SERVICE_UNAVAILABLE, "库存服务不可用")

幂等性：Idempotency-Key + t_idempotency 表，24h TTL
SLA：P99 < 200ms
监控：stock_service_reserve_qps / rt / error_rate / success_rate
版本兼容：仅向后兼容修改，破坏性变更必须升级 V2
```

### 8. 依赖原则

- **单向依赖**：禁止循环依赖（通过 IDE 检查或 ArchUnit）
- **稳定依赖**：依赖方向指向更稳定的模块
- **接口隔离**：客户端不应被迫依赖不需要的方法
- **最少知识**：调用方只依赖必要接口，不深入实现细节
- **内部调用超时**：Feign 读超时 3s，连接超时 1s，重试 0 次
- **内部鉴权**：所有 `/internal/` 路径必须 `X-Internal-Token` 验证

### 9. 版本管理

| 变更类型 | 是否兼容 | 处理方式 |
|----------|----------|----------|
| 新增字段（输出） | 兼容 | 直接发布 |
| 新增可选参数（输入） | 兼容 | 直接发布 |
| 修改字段类型/语义 | **不兼容** | 升级 V2，旧版并行运行 |
| 删除字段 | **不兼容** | 升级 V2 + 废弃标注 |
| 修改错误码 | **不兼容** | 升级 V2 + 映射表 |

### 10. 文档维护

- 接口变更**必须**同步更新本文档
- 同步更新调用方依赖检查
