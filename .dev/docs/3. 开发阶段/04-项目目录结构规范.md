## 文档目的

> 统一薄荷商城后台系统 Maven 多模块项目的目录结构，明确各服务子模块内部包分层契约与公共模块职责边界，确保模块职责清晰、依赖方向正确、易于扩展。

## 适用范围

- **适用对象**：所有后端研发、DevOps
- **适用场景**：新建模块、拆 Maven 多模块、调整包结构、代码评审
- **不适用范围**：单模块 Demo、纯前端/纯脚本项目

### 1.1 顶层 POM 依赖关系

```
minimall-gateway ──────────────────→ minimall-common
                                        ↑
各业务 service ──────→ minimall-api ────┘
```

- **所有服务** 依赖 `minimall-common`
- **业务服务**（非 gateway）额外依赖 `minimall-api`（Feign 接口 + 跨服务 DTO）
- **禁止** `minimall-common` 反向依赖任何服务模块
- **禁止** `minimall-api` 反向依赖任何服务模块
- **禁止** 服务间互相依赖源码（跨服务调用只走 Feign）

## 2. 网关服务结构（minimall-gateway）

网关为 Spring Cloud Gateway 响应式项目，不遵循 Controller/Service/Manager 分层。

## 5. 分层契约与关键约定

### 5.1 Controller 层

| 约定 | 说明 |
|------|------|
| **必须 V1 后缀** | 类名 `XxxControllerV1`，包路径 `controller/v1/` |
| **统一返回** | 方法返回值 `Result<XxxVO>`，禁止返 `Map` 或裸实体 |
| **入参** | 使用 `XxxDTO` + `@Valid` 校验，禁止用实体 PO 做入参 |
| **禁止 try-catch** | 异常由 `GlobalExceptionHandler` 统一处理，Controller 不吞异常 |

### 5.2 Service 层

| 约定 | 说明 |
|------|------|
| **禁止继承 IService** | `XxxServiceImpl` **不可** 继承 `IService<T>` / `ServiceImpl<M, T>` |
| **薄业务层** | 仅做参数校验、业务编排、调用 Manager，不含跨 Mapper 逻辑 |
| **接口 + 实现** | 必须定义接口 `XxxService` + 实现类 `XxxServiceImpl` |

### 5.3 Manager 层

| 约定 | 说明 |
|------|------|
| **必须继承 ServiceImpl** | `XxxManagerImpl` **必须** 继承 `IService<T>` + `ServiceImpl<M, T>`，复用 MP 通用 CRUD |
| **跨 Mapper 编排** | Manager 可注入多个 Mapper，完成跨聚合根操作 |
| **接口 + 实现** | 必须定义接口 `XxxManager` + 实现类 `XxxManagerImpl` |
| **@Manager 注解** | 实现类标注 `@Manager`，与 `@Service` 区分 |

### 5.4 POJO 类型边界

| 类型 | 用途 | 命名 | 位置 |
|------|------|------|------|
| PO | 数据库实体 | `XxxPO` | `entity/` |
| DTO | Controller 入参 | `XxxDTO` | `dto/` |
| VO | Controller 出参 | `XxxVO` | `vo/` |
| BO | Service 内部 | `XxxBO` | `bo/` |
| Feign DTO | 跨服务传输 | `XxxDTO` | `minimall-api` 的 `dto/` 下 |

### 5.5 枚举

- 放 `constant/` 包下
- 字段统一命名 `(code, alias, message)`
- 实现 `BaseEnum` 接口（在 `minimall-common` 定义）

## 7. 依赖方向与禁止事项

### 7.1 依赖方向（从上到下）

```
业务 Service 模块
  ├──→ minimall-api（Feign 接口 + 跨服务 DTO）
  └──→ minimall-common（通用工具 / 基类 / 异常）

minimall-api
  └──→ minimall-common

minimall-gateway
  └──→ minimall-common
```

### 7.2 禁止事项

| 禁止 | 原因 |
|------|------|
| ❌ `minimall-common` 依赖任何服务模块 | 公共模块不可反向依赖 |
| ❌ `minimall-api` 依赖任何服务模块 | 公共模块不可反向依赖 |
| ❌ 服务模块间互相依赖源码 | 跨服务调用只走 Feign |
| ❌ Service 继承 `IService<T>` / `ServiceImpl<M, T>` | 违反分层契约，Service 层保持薄业务 |
| ❌ Controller 返回 `Map<String, Object>` 或裸实体 | 必须用 `Result<XxxVO>` |
| ❌ Controller 内 `try-catch` 吞掉异常 | 由 `GlobalExceptionHandler` 统一处理 |
| ❌ 业务代码放入 `minimall-common` | common 只放通用基类/工具，不放业务逻辑 |
| ❌ 跨模块循环依赖 | Maven 不允许，设计上也不合理 |
| ❌ SQL 脚本散落多处 | 统一放 `db/migration/`，走版本化迁移 |
| ❌ 敏感信息明文写 `application.yml` | 走 Nacos + KMS 加密 |
