## 详细内容

### 1. 自研组件

#### 1.1 统一返回 `Result<T>`

位置：`com.yirancrazy.minimall.pojo.Result`

```text
class Result<T> {
  String  code        // "00000" 成功，"1xxxx" 业务错误，"2xxxx" 系统错误（阿里规约5位字符串）
  String  message     // 中文消息
  T       data        // 业务数据
  String  traceId     // 全链路追踪 ID
}

静态方法：
  Result.success() / Result.success(data)
  Result.fail(String code, String message)
  Result.fail(BizException e)
```

使用规范：

- Controller **必须**返 `Result<T>`，**禁止**直接返 VO 或 `ResponseEntity`
- 错误码 5 位字符串（阿里规约）：成功 `"00000"`，业务错误 `"1xxxx"`，系统错误 `"2xxxx"`，详见 [API 设计文档](../2.%20设计阶段/02-API设计文档.md) 错误码表
- 流式响应、文件下载直接返 `ResponseEntity` / `void`

#### 1.2 `@Manager` 自定义注解

位置：`com.yirancrazy.minimall.annotation.Manager`

```text
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Service
public @interface Manager {
  String value() default "";
}
```

使用（**必须**继承 `IService<T>` + `ServiceImpl<M, T>`，复用 MyBatis-Plus 通用 CRUD）：

```java
@Manager
public class UserOrderManager extends ServiceImpl<UserMapper, User> {
  private final OrderMapper orderMapper;
  private final InventoryMapper inventoryMapper;

  // 跨 Mapper 编排（直接用 getById / save / updateById 等继承自 IService 的方法）
  public void transferOrder(Long userId, OrderDTO dto) {
    User user = getById(userId);
    // ... 跨 user + order + inventory 的复杂编排
  }
}
```

- **必须**让 Manager 继承 `IService<T>` + `extends ServiceImpl<M, T>`，否则手写通用 CRUD 视为违规
- Service 通过构造注入 Manager
- Manager **禁止**反向依赖 Service
- Controller **禁止**直接调用 Manager
- 详细分层规则见 [MyBatis-Plus 规范 §4.1](03-MyBatis-Plus规范.md)

#### 1.3 分页响应 `PageResult<T>`

```text
class PageResult<T> {
  Long total
  Long pages
  Long current
  Long size
  List<T> records
}
```

- 与 MyBatis-Plus `Page<T>` 互转
- 序列化时 `current/size` 替代 `pageNo/pageSize`

#### 1.4 自定义异常 `BizException`

```text
class BizException extends RuntimeException {
  String code
  String message
  // ...
}
```

抛出：`throw new BizException("11001", "用户不存在")`（code 为 5 位字符串，alias 另存）

#### 1.5 分布式锁工具 `DistributedLock`

```java
boolean ok = distributedLock.tryLock("order:pay:" + orderId, 5, TimeUnit.SECONDS);
if (!ok) return Result.fail("14021", "操作频繁");
try {
  // 业务逻辑
} finally {
  distributedLock.unlock("order:pay:" + orderId);
}
```

- 基于 Redisson
- key 命名：`业务:场景:ID`
- 锁粒度最小化，**禁止**锁整个方法

#### 1.6 幂等注解 `@Idempotent`

```java
@Idempotent(key = "#req.orderNo", expire = 24, unit = TimeUnit.HOURS)
public Result<OrderVO> createOrder(OrderDTO req) { ... }
```

- 基于 Redis SETNX + Lua
- key 表达式支持 SpEL
- 重复请求直接返首次结果

#### 1.7 日志 MDC 工具 `TraceUtil`

```java
TraceUtil.setTraceId(UUID.randomUUID().toString());
try {
  // 业务
} finally {
  TraceUtil.clear();
}
```

- 配合 `logback-spring.xml` 输出 `%X{traceId}`
- 网关层自动注入 traceId，下游透传

### 2. 错误码体系

错误码为 5 位字符串格式（遵循《阿里规约 黄山版》），通过 `Result.code` 字段返回。

#### 2.1 码段分配表

| 码段 | 含义 | 归属服务 |
|------|------|----------|
| 00000 | 成功 | 全局 |
| 11xxx | 订单业务错误 | order-service |
| 12xxx | 支付业务错误 | pay-service |
| 13xxx | 商品业务错误 | goods-service |
| 14xxx | 认证/权限错误 | auth-service |
| 15xxx | 用户业务错误 | user-service |
| 16xxx | 商家业务错误 | merchant-service |
| 17xxx | 库存业务错误 | stock-service |
| 18xxx | 购物车业务错误 | cart-service |
| 19xxx | 通知业务错误 | notify-service |
| 20xxx | 平台业务错误 | platform-service |
| 21xxx-29xxx | 预留 | — |
| 2xxxx | 系统错误 | 全局 |

#### 2.2 占用规则

- 每个服务占用 1 个千位段，服务内百位/十位自定义，个位预留
- 同一服务内按子模块分配百位（如 order-service：110xx=订单创建，111xx=订单查询，112xx=退款）

#### 2.3 alias 字段

- alias 为语义短码（如 `TOKEN_EXPIRED`、`ORDER_NOT_FOUND`），用于日志和内部排查
- alias **不返回给前端**，前端仅依赖 code + message
- 抛出异常时：`throw new BizException("14001", "TOKEN_EXPIRED", "Token已过期")`

### 4. 使用规范

#### 4.1 Hutool vs Guava

- **优先**用 JDK 自带：`List.of()`、`Map.of()`、`Optional`
- 次选 Guava：`ImmutableList`、`Multimap`
- Hutool 仅作补充，**禁止** `StrUtil`、`CollUtil` 满天飞

#### 4.2 序列化

- 统一 Jackson，`spring.jackson.date-format=2026-07-27 HH:mm:ss`
- VO/DTO 加 `@JsonInclude(Include.NON_NULL)` 减少空字段
- 字段命名驼峰，禁止 `@JsonProperty` 乱改名
- 时间字段统一 `LocalDateTime` 序列化为字符串

#### 4.3 HTTP 客户端

- 内部 RPC：Spring Cloud OpenFeign
- 外部 HTTP：OkHttp + 统一封装
- **禁止**使用 HttpClient / URLConnection 原生

#### 4.4 限流

- 网关层：Sentinel / Spring Cloud Gateway
- 应用层：`@SentinelResource`
- 限流规则通过 Nacos 动态配置

#### 4.5 接口文档

- 集成 Knife4j
- Controller 必须有 `@Tag`、`@Operation`、`@Parameter`
- DTO 必须有 `@Schema` 描述
- 在线访问：`/doc.html`（仅 dev/staging 开放）

#### 4.6 时间处理

- 全局 `Clock` 单例（便于测试 mock）
- 业务时间用 `LocalDateTime` / `LocalDate`
- 时间戳（DB 主键、分布式 ID）用 `Instant` / `long`
- 时区统一 `ZoneId.systemDefault()` 配置化

### 5. 推荐但不强制

| 库 | 场景 |
|------|------|
| MapStruct | DTO/VO 转换 |
| Lombok | 必备 |
| Caffeine | 本地缓存 |
| Resilience4j | 熔断降级 |
| ShedLock | 分布式定时任务锁 |
| Testcontainers | 集成测试 |

### 6. 反模式（禁止）

- ❌ 重复造轮子（如自研 JSON 工具）
- ❌ 一个项目引入 2 套 HTTP 客户端
- ❌ 业务代码直接 `new Thread()`
- ❌ 在 Controller 写业务逻辑
- ❌ `SimpleDateFormat` 共享实例
- ❌ Hutool 替代所有工具（性能、依赖体积）
