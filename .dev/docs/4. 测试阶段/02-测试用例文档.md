## 文档目的

> 定义测试用例的模板、字段、覆盖度与维护流程，确保用例可执行、可追溯、可度量。

## 适用范围

- **适用对象**：测试、研发（自测）
- **适用场景**：用例设计、评审、回归
- **不适用范围**：纯探索式测试（无需文档化）

## 详细内容

### 1. 用例模板

| 字段 | 说明 |
|------|------|
| 用例 ID | TC-{模块}-{序号}，如 TC-ORDER-001 |
| 用例名称 | 简洁描述被测功能 |
| 优先级 | P0 / P1 / P2 / P3 |
| 前置条件 | 数据、环境、登录态 |
| 步骤 | 按顺序的操作 |
| 预期 | 可观察的结果 |
| 实际 | 测试执行后填写 |
| 状态 | 通过 / 失败 / 阻塞 / 跳过 |
| 关联需求 | PRD / SRS 章节或用户故事 ID |
| 设计人 | 编写者 |
| 执行人 | 测试执行者 |
| 自动化标记 | 是 / 否 + 脚本路径 |

### 2. 用例设计方法

| 方法 | 适用 |
|------|------|
| 等价类划分 | 输入域划分有效 / 无效 |
| 边界值 | 边界、刚越界 |
| 场景法 | 业务流（正常 + 异常） |
| 状态转换 | 状态机遍历 |
| 判定表 | 多条件组合 |
| 错误猜测 | 经验驱动的可疑点 |

### 3. 用例结构示例

#### 3.1 功能用例

```
TC-ORDER-001  正常下单
  优先级：P0
  前置：用户已登录、库存充足
  步骤：
    1. POST /api/v1/user/orders {productId: 1001, count: 1}
  预期：
    - HTTP 200
    - 返回 {code: "00000", data: {orderId: 非空, status: "PENDING"}}
    - 数据库 trade_order 增加一条记录
    - 库存扣减 1
  关联：US-002（用户故事）、PRD §3.1
  自动化：是，OrderControllerV1Test#should_createOrder_when_validRequest
```

#### 3.2 异常用例

```
TC-ORDER-002  库存不足
  优先级：P0
  前置：用户已登录、库存 = 0
  步骤：
    1. POST /api/v1/user/orders {productId: 1001, count: 1}
  预期：
    - HTTP 200
    - 返回 {code: "15001", message: "库存不足"}
  关联：US-002、PRD §3.1
  自动化：是
```

### 4. 覆盖度要求

| 层级 | 覆盖率 | 备注 |
|------|--------|------|
| 关键业务（下单/支付） | 100% | 路径 + 异常 |
| 一般业务 | ≥ 80% | 核心路径 |
| 边界 | ≥ 60% | 必含 0、最大、最小、空、null |
| 异常流 | ≥ 70% | 业务异常 + 系统异常 |
| 接口 | 100% | 每个接口 ≥ 1 正例 + 1 反例 |

### 5. 用例维护

- 每次需求变更**必须**更新对应用例
- 缺陷修复**必须**新增回归用例
- 定期 review，淘汰过时用例
- P0 用例**必须**自动化
- 详细自动化要求见 [自动化测试规范](04-自动化测试规范.md)

### 6. 用例管理工具

| 工具 | 适用 |
|------|------|
| Excel / 飞书表格 | 小团队、< 500 条 |
| TestLink / Zentao | 传统测试管理 |
| PingCode / TAPD | 研发一体化 |
| Xray（for Jira） | Jira 用户 |

**推荐**：研发一体化平台 + 自动化用例代码同仓库。

### 7. 用例评审清单

- [ ] 是否覆盖正常流、异常流、边界？
- [ ] 步骤是否具体可执行？
- [ ] 预期是否可观察、可验证？
- [ ] 是否关联需求 / 用户故事？
- [ ] P0 / P1 是否标记自动化？
- [ ] 是否存在重复用例？

### 8. 反模式（禁止）

- ❌ 步骤含模糊描述（"输入正确的数据"）
- ❌ 预期不可验证（"系统正常工作"）
- ❌ 一条用例覆盖多个独立功能
- ❌ 缺少前置条件
- ❌ 用例长期不更新，与实际功能脱节
