## 文档目的

> 定义缺陷（Bug）的分类、生命周期、流转规则与处理 SLA，保障缺陷被及时发现、定位、修复、关闭。

## 适用范围

- **适用对象**：测试、研发、产品
- **适用场景**：Bug 提交、跟踪、回归、关闭
- **不适用范围**：需求变更（见 [需求变更记录](../1.%20需求阶段/05-需求变更记录.md)）、技术债务（见 [迭代回顾记录](../6.%20项目管理/05-迭代回顾记录.md)）

## 详细内容

### 1. 严重级别

| 级别 | 标识 | 定义 | 例子 |
|------|------|------|------|
| P0 致命 | 💥 | 阻塞主流程、系统不可用、数据丢失 | 登录失败、支付丢单、OOM |
| P1 严重 | 🔴 | 核心功能异常、无可用 workaround | 订单无法取消、库存计算错误 |
| P2 一般 | 🟡 | 次要功能异常、有 workaround | 列表分页错乱、提示文案错误 |
| P3 轻微 | 🟢 | UI/文案/体验问题 | 颜色不一致、错别字 |
| P4 建议 | 💡 | 优化建议 | 提示信息可更友好 |

### 2. 优先级

| 优先级 | 含义 |
|--------|------|
| Urgent | 24h 内修复（线上 P0） |
| High | 本迭代内修复 |
| Medium | 下个迭代修复 |
| Low | 排期讨论 |

### 3. Bug 状态机

```
新建 → 待复核 → 待修复 → 修复中 → 待回归 → 已关闭
  │       │         │        │         │        ↑
  └───────┴─────────┴────────┴─────────┴────────┘
                  (任意状态可打回)
```

| 状态 | 说明 | 责任人 |
|------|------|--------|
| 新建 | 测试提交 | 测试 |
| 待复核 | 研发确认可复现 | 研发 |
| 待修复 | 排期中 | 研发 |
| 修复中 | 开发处理 | 研发 |
| 待回归 | 已修复待验证 | 测试 |
| 已关闭 | 验证通过或非问题 | 测试 |
| 打回 | 不可复现 / 非问题 / 需求变更 | 研发 / 产品 |
| 延期 | 排到后续迭代 | 产品 |

### 4. Bug 模板

```
【Bug 标题】一句话描述问题

环境：dev / staging / prod + 浏览器/版本
复现步骤：
  1. 登录账号 A
  2. 进入订单页
  3. 点击取消按钮
预期：弹出确认框
实际：直接取消，无确认

严重级别：P1
优先级：High
关联需求：US-005 / PRD §3.2
截图/录屏：（附件）
日志：（traceId）
```

### 5. SLA

| 级别 | 响应 | 修复 | 回归 |
|------|------|------|------|
| P0 致命 | 立即 | ≤ 4h | 24h |
| P1 严重 | 4h | ≤ 1d | 3d |
| P2 一般 | 1d | ≤ 3d | 7d |
| P3 轻微 | 3d | 下迭代 | - |
| P4 建议 | 1w | 评估 | - |

### 6. 处理流程

```
测试发现 → 提交 Bug → 研发确认 → 排期 → 修复 → 提测 → 回归 → 关闭
   │          │         │         │      │      │      │     ↑
   │          │         │         │      │      │      └─────┘
   │          │         │ 不可复现 → 打回    │   验证不通过
   │          │         └──── 需求变更 → 走变更流程
   │          └── 重复 Bug → 合并到已有 Bug
   └── 线上 P0 → 立即响应，启动应急流程
```

### 7. 线上故障应急

- P0 故障**必须**立即响应，30 分钟内启动应急
- 流程：发现 → 通知值班 → 止血（回滚 / 切流 / 关闭入口）→ 定位 → 修复 → 复盘
- 详细见 [故障排查手册](../5.%20部署阶段/08-故障排查手册.md)
- 故障复盘材料归档到 [迭代回顾记录](../6.%20项目管理/05-迭代回顾记录.md)

### 8. 度量指标

| 指标 | 计算 | 目标 |
|------|------|------|
| Bug 发现率 | 迭代 Bug 数 / 需求数 | 趋势稳定 |
| 平均修复时长 | 修复时间 - 提交时间 | P1 ≤ 1d |
| 重开率 | 重开 Bug / 关闭 Bug | < 10% |
| 漏测率 | 线上 Bug / 总 Bug | < 5% |
| 趋势 | 每周 P0/P1 数量 | 收敛 |

### 9. 反模式（禁止）

- ❌ Bug 描述模糊（"功能异常"）
- ❌ 严重级别不标或错标
- ❌ 修复后不通知测试回归
- ❌ 研发直接关闭而非转"待回归"
- ❌ 同一 Bug 多人同时处理
- ❌ 长期未关闭的"僵尸" Bug（需定期清理）
