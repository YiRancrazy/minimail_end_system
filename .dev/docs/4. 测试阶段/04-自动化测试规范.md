## 文档目的

> 规范自动化测试框架选型、用例组织、CI 集成与维护策略，提升回归效率与交付质量。

## 适用范围

- **适用对象**：测试开发、研发
- **适用场景**：回归测试、CI 流水线、E2E 验证
- **不适用范围**：纯人工探索式测试

## 详细内容

### 1. 测试分层与工具

| 层 | 工具 | 范围 | 速度 |
|------|------|------|------|
| 单元测试 | JUnit 5 + Mockito | Service / Manager / Util | 极快 |
| 切片测试 | Spring `@WebMvcTest` / `@DataJpaTest` | Controller / Repository | 快 |
| 集成测试 | Spring Boot Test + Testcontainers | 多模块联调 | 中 |
| 契约测试 | Spring Cloud Contract | 服务间接口 | 中 |
| E2E（前端） | Playwright / Cypress | 关键用户旅程（浏览器 UI） | 慢 |
| E2E（后端） | JUnit 5 + RestAssured | 关键业务链路（HTTP API） | 慢 |
| 性能 | JMeter / Gatling | 接口压测 | 离线 |

详细分层见 [测试策略与计划](01-测试策略文档.md)。

### 2. 后端自动化（Java）

#### 2.1 依赖

| 依赖 | 用途 |
|------|------|
| `spring-boot-starter-test` | Spring 测试套件 |
| `org.junit.jupiter:junit-jupiter` | JUnit 5 |
| `org.mockito:mockito-core` | Mock 框架 |
| `org.testcontainers:*` | Docker 化中间件 |
| `com.h2database:h2` | 内存数据库（test profile） |
| `org.assertj:assertj-core` | 流畅断言 |

#### 2.2 目录与命名

```
src/test/java
├── controller/      # @WebMvcTest
├── service/         # 纯单测
├── manager/         # Mock 多个 Mapper
├── mapper/          # @MybatisPlusTest
├── integration/     # 完整 SpringBootTest
└── util/

src/test/resources
├── application-test.yml
├── init.sql
├── cleanup.sql
└── mockdata/
```

- 测试类名：`{被测类}Test`
- 方法名：`should_{预期}_when_{条件}`，允许中文
- 同一类按被测类放同包（保留包结构）

#### 2.3 关键注解

| 注解 | 用途 |
|------|------|
| `@SpringBootTest` | 启动完整上下文 |
| `@WebMvcTest(XxxController.class)` | 仅 Web 层 |
| `@DataJpaTest` | 仅 JPA 仓储 |
| `@MybatisPlusTest` | MyBatis-Plus Mapper |
| `@MockBean` | 替换 Bean 为 Mock |
| `@Sql(scripts=..., executionPhase=...)` | 初始化 / 清理数据 |
| `@DisplayName("...")` | 友好测试名 |
| `@ParameterizedTest` | 参数化 |
| `@Timeout(value=5, unit=SECONDS)` | 超时保护 |

#### 2.4 单元测试示例

```java
@DisplayName("用户服务单测")
class UserServiceTest {
  @InjectMocks
  private UserService userService;
  @Mock
  private UserMapper userMapper;

  @Test
  @DisplayName("根据 ID 查询用户 - 存在")
  void should_returnUser_when_idExists() {
    Long id = 1L;
    UserPO user = new UserPO();
    user.setId(id);
    user.setName("张三");
    when(userMapper.selectById(id)).thenReturn(user);

    UserVO vo = userService.getById(id);

    assertThat(vo).isNotNull();
    assertThat(vo.getName()).isEqualTo("张三");
  }

  @Test
  void should_throwBizException_when_userNotFound() {
    when(userMapper.selectById(anyLong())).thenReturn(null);
    assertThatThrownBy(() -> userService.getById(1L))
      .isInstanceOf(BizException.class)
      .hasMessage("用户不存在");
  }
}
```

#### 2.5 集成测试示例

```java
@SpringBootTest
@Testcontainers
class OrderIntegrationTest {
  @Container
  static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
    .withDatabaseName("test");

  @DynamicPropertySource
  static void props(DynamicPropertyRegistry r) {
    r.add("spring.datasource.url", mysql::getJdbcUrl);
    r.add("spring.datasource.username", mysql::getUsername);
    r.add("spring.datasource.password", mysql::getPassword);
  }

  @Autowired OrderService orderService;

  @Test
  void should_createOrder_end2end() {
    OrderDTO req = new OrderDTO();
    req.setUserId(1L); req.setProductId(100L); req.setCount(1);
    OrderVO vo = orderService.createOrder(req);
    assertThat(vo.getId()).isNotNull();
  }
}
```

### 3. 前端自动化（Vue）

- 工具：Vitest + Vue Test Utils + Playwright
- 组件测试：props、events、slots
- E2E：关键用户旅程（注册、登录、下单、支付）
- 覆盖率核心组件 ≥ 80%

### 4. CI 集成

#### 4.1 流水线阶段

```
代码拉取 → 编译 → 单元测试 → 覆盖率 → 静态扫描 → 契约测试 → 镜像构建 → 部署
```

#### 4.2 触发条件

| 触发 | 执行 |
|------|------|
| PR | 单元 + 切片 + 静态扫描 |
| Merge main | 全量 + 契约 + 集成 |
| Tag | + 性能冒烟 + E2E |
| 定时（每日） | 全量回归 |

#### 4.3 失败处理

- 单元测试失败 → 阻断合并
- 覆盖率不达标 → 阻断合并（< 70%）
- E2E 失败 → 自动创建 Bug + 通知

### 5. 数据准备

| 场景 | 方案 |
|------|------|
| 单元测试 | Builder 模式构造对象 |
| 集成测试 | `@Sql` + fixture 文件 |
| 容器化 | Testcontainers 启动真实依赖 |
| 大量数据 | SQL 脚本 + `@Sql` |
| 动态数据 | `@MethodSource` / `@Random` |

### 6. 稳定性

- **禁止**依赖执行顺序（`@TestMethodOrder` 仅在无法避免时）
- **禁止**硬编码线程休眠（`Thread.sleep`），用 `Awaitility`
- 外部依赖一律 Mock 或 Testcontainers
- 失败用例加 `@Disabled` 必须注明原因 + Issue 链接
- 偶发性用例加 `@Flaky` 标记，跟踪重试机制

### 7. 度量

| 指标 | 目标 |
|------|------|
| 单元测试覆盖率 | ≥ 70%（关键模块 ≥ 85%） |
| 测试执行时长 | 单元 < 10min、全量 < 60min |
| 用例通过率 | ≥ 99% |
| 自动化用例占比 | P0 用例 100% |
| 缺陷逃逸率 | < 5% |

### 8. 维护

- 每次需求变更**同步**更新用例
- 失败用例 24h 内响应（修复 / 加 `@Disabled`）
- 定期清理 `@Disabled` 用例（最长保留 1 个迭代）
- 测试代码与生产代码同等 Code Review

### 9. 反模式（禁止）

- ❌ 测试用例只覆盖正常流
- ❌ `@SpringBootTest` 测单个 Service
- ❌ 强依赖网络 / 真实 DB
- ❌ `Thread.sleep` 等待异步
- ❌ 一个测试方法覆盖多个功能
- ❌ 失败用例长期 `@Disabled` 无后续
