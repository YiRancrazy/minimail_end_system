## 详细内容

## 1. 适用版本
- 应用版本：`1.0.0`
- JDK 版本：`JDK 17`
  **【必须】** 生产环境使用 LTS 版本 JDK，禁止使用非长期支持版本。

## 2. 环境要求
### 2.1 操作系统
- 推荐 Linux（CentOS 7.x+ / Ubuntu 20.04+）
- 内核参数已按高并发场景优化（见 2.4）

### 2.2 中间件依赖
| 组件 | 版本 | 用途 |
|------|------|------|
| MySQL | 8.0.x | 主库 |
| Redis | 7.2.4 | 缓存 |
| RocketMQ | 5.x | 消息队列 |
| Nacos | 2.x | 配置/注册中心 |
| … | … | … |

### 2.3 基础环境配置  
**【必须】**  
1. **系统时区**：`Asia/Shanghai` (`ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime`)  
2. **系统编码**：`LANG=zh_CN.UTF-8`，应用读写文件统一使用 `UTF-8`。  
3. **主机名**：有意义的小写主机名，禁止使用 `localhost`。

### 2.4 操作系统参数优化（参考高并发场景）
```bash
# 减少 TIME_WAIT，快速回收 TCP 连接（高并发服务器必须）
echo 1 > /proc/sys/net/ipv4/tcp_tw_reuse
echo 1 > /proc/sys/net/ipv4/tcp_tw_recycle
# 扩大端口范围
echo 1024 65535 > /proc/sys/net/ipv4/ip_local_port_range
# 调整最大文件句柄数
ulimit -n 65535
```
以上参数需写入 `/etc/sysctl.conf` 及 `/etc/security/limits.conf` 保持永久生效。

## 3. 部署目录规范
**【必须】** 遵循统一目录结构，应用专属用户启动。
- 应用部署根目录：`/app/minimall`
- 程序包路径：`/app/minimall/current/`
- 日志目录：`/app/logs/minimall/`
- 配置文件：`/app/minimall/config/`
- 启动用户：**【强制】** 非 root 用户，推荐 `nobody` 或专属应用账户（例如 `appuser`），禁止使用 `admin` 或 `root` 启动。

## 4. JVM 参数配置
**【必须】** 使用启动脚本启动，禁止直接使用 `java -jar` 方式。  
**【推荐】** JVM 参数遵循以下原则：
- `-Xms` 与 `-Xmx` 大小一致，避免内存动态伸缩带来的 GC 压力。
- `-XX:MetaspaceSize` 与 `-XX:MaxMetaspaceSize` 大小一致。
- 显式指定 GC 算法（如 G1：`-XX:+UseG1GC`）。
- 开启 GC 日志（方便故障排查）。

**模板示例（2核4G 内存容器/主机，根据实际调整）**：
```bash
JAVA_OPTS="-server -Xms2g -Xmx2g -Xmn1g \
           -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=256m \
           -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
           -XX:+PrintGCDetails -XX:+PrintGCDateStamps \
           -Xloggc:/app/logs/minimall/gc.log \
           -XX:+HeapDumpOnOutOfMemoryError \
           -XX:HeapDumpPath=/app/logs/minimall/heapdump.hprof \
           -Djava.security.egd=file:/dev/./urandom"
```

## 5. 应用配置
### 5.1 线程池命名
**【强制】** 线程池必须提供有意义的名称，便于问题追踪：
```properties
# Spring 线程池示例
spring.task.execution.pool.core-size=8
spring.task.execution.pool.max-size=16
spring.task.execution.thread-name-prefix=order-task-
```

### 5.2 数据库连接池（以 Druid 为例）
**【必须】** 明确配置初始化连接数、最小/最大连接数，禁止使用默认无限大连接池。
```properties
spring.datasource.druid.initial-size=5
spring.datasource.druid.min-idle=5
spring.datasource.druid.max-active=20
spring.datasource.druid.test-while-idle=true
spring.datasource.druid.validation-query=SELECT 1
```
数据库密码【必须】经过加密存储，禁止明文，推荐使用配置中心或密钥管理服务。

### 5.3 日志配置
**【必须】** 日志文件保存天数至少保留 15 天。  
**【推荐】** 使用日志框架占位符输出，禁止字符串拼接；禁止输出敏感信息（身份证、手机号、密码等）。
```properties
logging.file.path=/app/logs/minimall
logging.pattern.file=%d{yyyy-MM-dd HH:mm:ss.SSS} [%X{traceId}] [%thread] %-5level %logger{36} - %msg%n
logging.file.max-history=15
```

## 6. 部署步骤（发版流程）
1. **通知**：提前发布维护公告 / 群通知。
2. **备份**：备份当前运行程序包、配置文件及数据库（如需）。
3. **停止服务**：执行 `/app/minimall/bin/stop.sh`，确认进程已退出。
4. **部署新包**：上传新程序包到 `/app/minimall/current/`，更新配置文件。
5. **启动服务**：执行 `/app/minimall/bin/start.sh`。
6. **健康检查**：观察启动日志、调用健康检查接口，确认服务正常。
7. **回滚预案**：如启动失败，重新替换为上一版本程序包，启动，验证。

## 7. 启动与停止脚本
### start.sh
```bash
#!/bin/bash
source /etc/profile
APP_HOME=/app/minimall
cd $APP_HOME/current
JAVA_OPTS="...详见第5节..."
nohup java $JAVA_OPTS -jar minimall.jar > /dev/null 2>&1 &
echo $! > $APP_HOME/app.pid
```
### stop.sh
```bash
#!/bin/bash
APP_HOME=/app/minimall
if [ -f $APP_HOME/app.pid ]; then
    kill -15 `cat $APP_HOME/app.pid`
    rm -f $APP_HOME/app.pid
fi
```
**注意**：脚本中必须设置可执行权限，启动前检查是否以 `appuser` 身份运行。

## 8. 健康检查
- **端口探活**：`curl -s 127.0.0.1:8080/actuator/health | grep UP`
- **业务检查接口**：自定义 `/health/check` 返回业务关键状态（DB、Redis、MQ等）。
- 定时轮询间隔建议 30 秒，连续失败 3 次触发告警。

## 9. 监控与告警
- **系统指标**：CPU、内存、磁盘、网络（Prometheus + Grafana / Zabbix）。
- **JVM 指标**：堆内存、线程数、GC 次数/耗时、类加载等。
- **中间件指标**：数据库连接池活跃数、Redis 命中率、MQ 积压量。
- **业务指标**：请求量、错误率、响应时间（接入 SkyWalking/Pinpoint）。
- **告警通道**：钉钉/企业微信/邮件，必须覆盖核心接口不可用、磁盘满、OOM 等致命事件。

## 10. 日志管理
- 日志文件滚动策略：按天切割，保留至少 15 天（`maxHistory=15`）。
- 日志归档：超过保留期的日志由 cron 定期删除。
- 禁止向 stdout/stderr 输出海量日志；生产环境需将控制台日志重定向至文件或关闭。
- 定期关注 `error` 关键字告警。

## 11. 数据备份与恢复
- **数据库**：每日全量备份 + binlog 增量备份，保留至少 30 天。
- **恢复演练**：每季度执行一次备份恢复演练，验证备份有效性。
- **文件存储**：重要文件（如上传文件）使用对象存储并开启多版本/跨区域复制。

## 12. 扩容与高可用
- 应用无状态设计，支持水平扩容。
- 通过负载均衡（Nginx/SLB）分发流量，至少 2 个实例避免单点。
- 会话信息外置到 Redis，禁止使用本地 Session。
- 数据库/缓存采用主从+哨兵/集群方案。

## 13. 应急预案
- **OOM 自动转储**：已配置 `-XX:HeapDumpOnOutOfMemoryError`，需保留 dump 文件用于分析。
- **服务雪崩**：配置限流/熔断规则（Sentinel，项目已选型），降级预案触发后返回兜底结果。
- **数据库主库故障**：切换从库为临时主库，修复后恢复拓扑。
- **紧急回滚**：见第6节回滚步骤，目标回滚时长 ≤ 5 分钟。
