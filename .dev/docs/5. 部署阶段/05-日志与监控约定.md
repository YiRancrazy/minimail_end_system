## 详细内容

### 1. 日志规范

#### 1.1 框架

- 使用 Logback（默认）或 Log4j2
- 通过 `logback-spring.xml` 配置
- 支持按环境（dev/test/staging/prod）输出

#### 1.2 日志格式

```text
%d{yyyy-MM-dd HH:mm:ss.SSS} [%X{traceId}] [%thread] %-5level %logger{36} - %msg%n
```

示例：
```
2026-07-27 10:23:45.123 [a1b2c3d4] [http-nio-8080-exec-1] INFO  com.yirancrazy.order.OrderService - 创建订单 orderId=10001 userId=2001 amount=99.00
```

生产环境使用JSON结构化日志（ADR-040），通过Logback Logstash encoder输出：

```xml
<appender name="JSON_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
  <file>/app/logs/minimall/app.json</file>
  <encoder class="net.logstash.logback.encoder.LogstashEncoder">
    <includeMdcKeyName>traceId</includeMdcKeyName>
    <includeMdcKeyName>spanId</includeMdcKeyName>
    <includeMdcKeyName>userId</includeMdcKeyName>
  </encoder>
</appender>
```

SkyWalking agent自动注入spanId到MDC。

#### 1.3 日志级别

| 级别 | 用途 | 例子 |
|------|------|------|
| ERROR | 系统异常、需介入 | 业务处理失败、DB 不可用 |
| WARN | 可恢复异常 | 重试、降级、参数缺失 |
| INFO | 关键业务节点 | 订单创建、支付回调、登录成功 |
| DEBUG | 调试信息（默认关闭） | SQL 参数、变量值 |
| TRACE | 最详细（默认关闭） | 进入 / 退出方法 |

#### 1.4 强制要求

- ✅ 关键业务操作（订单、支付、登录）记录 INFO
- ✅ 异常记录 ERROR（含堆栈、traceId）
- ✅ 禁止字符串拼接，用占位符：`log.info("user={}", userId)`
- ✅ 禁止输出敏感信息：密码、手机号、身份证、银行卡、token
- ✅ 用户手机号脱敏：`138****8001`
- ✅ 线程池、MQ 消费、定时任务必须打日志

#### 1.5 反模式

- ❌ `System.out.println` / `System.err.println`
- ❌ `log.info("user=" + userId)`（拼接）
- ❌ 异常仅 `e.printStackTrace()` 不打 ERROR
- ❌ 循环内大量 DEBUG 日志
- ❌ 敏感信息明文输出

#### 1.6 日志文件管理

```xml
<appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
  <file>/app/logs/minimall/app.log</file>
  <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
    <fileNamePattern>/app/logs/minimall/app.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
    <maxFileSize>100MB</maxFileSize>
    <maxHistory>30</maxHistory>
    <totalSizeCap>50GB</totalSizeCap>
  </rollingPolicy>
  <encoder>
    <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%X{traceId}] [%thread] %-5level %logger{36} - %msg%n</pattern>
  </encoder>
</appender>
```

日志保留策略（ADR-058）：
- Loki存储30天热数据，支持快速查询
- S3/OSS归档90天满足合规要求
- 成本可控，兼顾查询效率与合规

- **必须**按天滚动，保留 ≥ 15 天（生产 30 天）
- 单文件 ≤ 100MB，压缩归档
- 禁止向 `stdout` / `stderr` 输出（容器场景会丢失）

### 2. 链路追踪

#### 2.1 工具

- SkyWalking（推荐）或 Zipkin / Jaeger

#### 2.2 traceId 透传

- 网关层生成 `traceId`（UUID），写入 MDC + 响应 Header
- HTTP 调用通过 `traceparent` (W3C) / `sw8` (SkyWalking) 透传
- MQ 消息 Header 携带 traceId
- 异步任务 / 定时任务起始处生成新 traceId

#### 2.3 日志关联

- 所有日志通过 `traceId` 关联
- 通过 traceId 可在 SkyWalking 看到完整调用链

### 3. 监控指标

#### 3.1 指标采集

- 工具：Micrometer + Prometheus
- 暴露端点：`/actuator/prometheus`
- 采集：Prometheus → Grafana

#### 3.2 指标分类

| 类别 | 指标 |
|------|------|
| JVM | heap / non-heap / GC / thread / class |
| HTTP | `http.server.requests`（QPS / RT / 状态码） |
| DB | 连接池活跃 / 等待 / 慢 SQL |
| Redis | 连接数 / 命中率 / 慢命令 |
| MQ | 生产 / 消费速率 / 积压量 |
| 业务 | 自定义指标（下单数、支付成功率） |

#### 3.3 自定义指标示例

```java
Counter.builder("order.create.count")
  .tag("channel", "app")
  .register(meterRegistry)
  .increment();

Timer.builder("payment.callback.duration")
  .publishPercentiles(0.95, 0.99)
  .register(meterRegistry)
  .record(duration, TimeUnit.MILLISECONDS);
```

### 4. 健康检查

| 端点 | 用途 | K8s 探针 |
|------|------|----------|
| `/actuator/health` | 总体健康 | - |
| `/actuator/health/liveness` | 存活探针 | livenessProbe |
| `/actuator/health/readiness` | 就绪探针 | readinessProbe |

- 自定义健康指示器：DB / Redis / MQ / 外部依赖
- 任意依赖不可用 → readiness = DOWN → 流量不进入
- 进程崩溃 → liveness 失败 → K8s 重启 Pod

### 5. 告警

#### 5.1 告警分级

告警渠道（ADR-059）：仅使用邮件告警。

| 级别 | 通道 | 响应 |
|------|------|------|
| P0 紧急 | 邮件 | 5 分钟 |
| P1 严重 | 邮件 | 15 分钟 |
| P2 一般 | 邮件 | 1 小时 |
| P3 提示 | 邮件 | 次日处理 |

#### 5.2 告警规则

- 错误率 > 1% 持续 5 分钟
- 接口 P99 > 1s 持续 5 分钟
- JVM 堆使用 > 80% 持续 10 分钟
- DB 连接池使用 > 90%
- Redis 命中率 < 80%
- MQ 积压 > 10000
- 健康检查连续 3 次失败

详细配置见 [监控告警文档](06-监控告警文档.md)。

### 6. 仪表盘

必备大盘：

- **总览**：QPS、RT、错误率、Pod 数
- **JVM**：堆 / GC / 线程
- **DB / Redis / MQ**：连接、慢查询、积压
- **业务**：订单量、支付成功率、登录量

每个业务域可单独建大盘。

### 7. 日志平台

- 采集：Filebeat / Fluentd / Promtail
- 存储：Elasticsearch / Loki
- 展示：Kibana / Grafana
- 字段：traceId / level / service / host / msg

### 8. 反模式（禁止）

- ❌ 监控盲区（核心接口无指标）
- ❌ 告警风暴（无收敛）
- ❌ 告警无人响应（无 oncall 机制）
- ❌ 日志无 traceId，无法关联
- ❌ 健康检查过宽松（DB 挂了仍 UP）
