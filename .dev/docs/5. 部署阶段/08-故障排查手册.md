## 文档目的

> 提供常见故障的快速定位、诊断与恢复步骤，缩短 MTTR（平均恢复时间）。

## 适用范围

- **适用对象**：运维、SRE、研发（值班）
- **适用场景**：线上故障响应
- **不适用范围**：需求缺陷（见 [缺陷管理流程](../4.%20测试阶段/03-缺陷管理流程.md)）

## 详细内容

### 1. 故障分级

| 级别 | 影响 | 响应 |
|------|------|------|
| P0 | 全站不可用、核心业务中断 | 立即（5min） |
| P1 | 核心功能异常、影响多数用户 | 15min |
| P2 | 次要功能异常、影响少数用户 | 1h |
| P3 | 体验问题、无业务影响 | 4h |

### 2. 应急流程

```
发现 → 确认 → 通知 → 止血 → 定位 → 修复 → 验证 → 复盘
 │       │       │       │       │       │       │       │
 监控    oncall  钉钉    回滚    链路   代码   测试   归档
 告警                          切流   日志   验证   记录
```

- 优先**止血**（回滚、切流、关闭入口），再**定位**
- 任何操作先通知再执行（紧急情况可后补通知）

### 3. 常见故障处理

#### 3.1 应用启动失败

**症状**：`/actuator/health` 返回 DOWN 或启动超时

**排查步骤**：

1. 查看启动日志：
   ```bash
   tail -500 /app/logs/minimall/startup.log
   ```
2. 常见原因：
   - 数据库连接失败 → 检查 `application-prod.yml` 配置、DB 状态、网络
   - Nacos 不可达 → 检查 Nacos 服务地址、网络 ACL
   - 端口被占用 → `lsof -i:8080` / `netstat -ano | findstr 8080`
   - JVM 参数错误 → 检查 `JAVA_OPTS`、堆内存设置
3. 修复：调整配置后重启；或回滚到上一版本

#### 3.2 接口 5xx 飙升

**症状**：监控告警 5xx 比例 > 1%

**排查步骤**：

1. 查 Grafana 大盘：错误率、RT、JVM、依赖
2. 通过 traceId 拉 SkyWalking 调用链
3. 看错误日志：定位根因服务 / 方法
4. 常见原因：
   - DB 慢 SQL / 死锁 → 查 slow log
   - 外部接口超时 → 限流 / 降级
   - OOM → 见 §3.4
   - 缓存击穿 → 加互斥锁 / 布隆过滤器

#### 3.3 接口响应慢

**症状**：P99 > 1s

**排查步骤**：

1. 慢接口排行：Grafana → 业务监控
2. 查慢 SQL：`SHOW PROCESSLIST` + `EXPLAIN`
3. 查 N+1：MyBatis 日志 + Mapper 检查
4. 缓存命中率：Redis 监控
5. 线程池状态：`jstack` 看阻塞

#### 3.4 OOM（内存溢出）

**症状**：服务自动重启、响应超时、报警

**排查步骤**：

1. 保留 heap dump（已配置自动 dump 到 `/app/logs/minimall/heapdump.hprof`）
2. 拉 dump 文件本地用 MAT / VisualVM 分析
3. 常见原因：
   - 大对象未释放（如分页未限制 `LIMIT`）
   - 缓存无界增长（Caffeine 无 maxSize）
   - 线程局部变量堆积（ThreadLocal 未清理）
   - JVM 堆设置过小
4. 应急：扩容 + 重启 + 限流

**预防**：
- `-Xms == -Xmx`
- 启用 `-XX:+HeapDumpOnOutOfMemoryError`
- 监控堆使用 > 80% 告警

#### 3.5 数据库故障

**症状**：连接超时、查询超时、主从延迟

**排查步骤**：

1. DB 存活：`mysqladmin ping` / `SELECT 1`
2. 连接数：`SHOW STATUS LIKE 'Threads_connected'`
3. 慢查询：`SHOW FULL PROCESSLIST` + `slow_query_log`
4. 主从状态：`SHOW SLAVE STATUS`（Seconds_Behind_Master）
5. 锁等待：`SELECT * FROM information_schema.INNODB_LOCK_WAITS`
6. 应急：
   - 主库挂 → 切从库（需提前演练）
   - 慢 SQL → kill 进程 + 优化 SQL
   - 连接池满 → 临时扩容 max-active

#### 3.6 Redis 故障

**症状**：缓存读写失败、连接超时

**排查步骤**：

1. `redis-cli ping` → PONG
2. `redis-cli info` → 内存、连接、命中率
3. `redis-cli slowlog get` → 慢命令
4. 大 key：`redis-cli --bigkeys`
5. 应急：降级为本地缓存 / 直查 DB（需提前设计）

#### 3.7 MQ 积压

**症状**：监控告警积压量 > 阈值

**排查步骤**：

1. 看消费者日志、QPS
2. 消费者是否正常（线程数、机器资源）
3. 是否有死信 / 失败重试
4. 应急：
   - 临时扩容消费者
   - 跳过非关键消息
   - 紧急清理（业务确认可丢）

#### 3.8 第三方接口超时

**症状**：调用方超时告警

**排查步骤**：

1. 确认对方服务状态（看对方监控 / 联系对方）
2. 自身连接池是否打满
3. 是否网络问题（traceroute / telnet）
4. 应急：
   - 降级：返回默认值 / 缓存
   - 限流：保护自身
   - 熔断：Sentinel / Resilience4j 临时熔断

| 工具 | 用途 |

| Grafana | 监控大盘 |

### 5. 应急工具

#### 5.1 Arthas 常用命令

```bash
# 1. 进入容器
kubectl exec -it ${pod} -n prod -- bash

# 2. 下载 arthas
curl -O https://arthas.aliyun.com/arthas-boot.jar

# 3. 启动
java -jar arthas-boot.jar

# 4. 常用命令
dashboard        # 总览
thread -n 3      # 最忙 3 个线程
watch com.yirancrazy.order.OrderService createOrder '{params,returnObj,throwExp,target,cost}' -x 2
trace com.yirancrazy.order.OrderService createOrder '#cost > 100' -n 1
jad --source-only com.yirancrazy.order.OrderService createOrder
ognl '@com.yirancrazy.order.OrderService@INSTANCE'
```

### 7. 反模式（禁止）

- ❌ 直接重启服务而不查根因
- ❌ 长时间定位未先止血
- ❌ 故障处理无时间线记录
- ❌ 复盘流于形式，无 action item
- ❌ 关键应急操作未演练
