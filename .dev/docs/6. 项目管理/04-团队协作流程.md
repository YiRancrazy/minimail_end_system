## 文档目的

> 统一团队协作的流程、节奏、角色与会议规范，提升协作效率与交付质量。

## 适用范围

- **适用对象**：全体项目成员
- **适用场景**：日常协作、迭代管理、跨团队协调
- **不适用范围**：纯个人工作

## 详细内容

### 1. 角色与职责

| 角色 | 主要职责 |
|------|----------|
| 产品负责人（PO） | 需求优先级、产品愿景、对外沟通 |
| 研发负责人（TL） | 技术决策、架构、进度把控 |
| 后端开发（RD-BE） | 后端开发、自测、Code Review |
| 前端开发（RD-FE） | 前端开发、联调、自测 |
| 测试（QA） | 测试用例、Bug、自动化 |
| 运维 / SRE | 发布、监控、应急响应 |
| UI / UX | 视觉、交互、原型 |
| Scrum Master | 流程促进、移除障碍 |

### 2. 研发模式

| 模式 | 适用 | 周期 |
|------|------|------|
| Scrum | 需求相对稳定、跨职能团队 | 2-4 周迭代 |
| Kanban | 运维、持续交付 | 持续 |
| 瀑布 | 合规、硬件耦合项目 | 长周期、阶段门 |

**本项目默认采用 Scrum**（2 周迭代），运维/支持类工作用 Kanban。

### 3. 迭代节奏

```
Day 0  : 迭代计划会（2h）
Day 0-9: 日常开发 + 每日站会（15min）
Day 5  : 中期检查（可选）
Day 8  : 集成测试开始
Day 9  : 评审会（1h）+ 回顾会（1h）
Day 10 : 演示日 + 迭代收尾
```

### 4. 核心会议

#### 4.1 迭代计划会

| 项 | 说明 |
|------|------|
| 时间 | 迭代开始第一天 |
| 时长 | 2h |
| 参与者 | 全员 |
| 议程 | 1) 回顾上个迭代 2) 展示本迭代目标 3) 拆分任务 4) 估时认领 |
| 输出 | 迭代 Backlog、每个人的任务列表 |
| 主持 | Scrum Master |

#### 4.2 每日站会

| 项 | 说明 |
|------|------|
| 时间 | 每天上午固定时间 |
| 时长 | 15min |
| 参与者 | 团队全员 |
| 议程 | 每人 1min：昨天做了什么 / 今天做什么 / 有什么阻碍 |
| 原则 | 站会不解决问题，阻塞项会后单聊 |
| 主持 | Scrum Master（轮值） |

#### 4.3 评审会

| 项 | 说明 |
|------|------|
| 时间 | 迭代最后一天 |
| 时长 | 1h |
| 参与者 | 全员 + 干系人 |
| 议程 | 演示本迭代完成的需求，收集反馈 |
| 输出 | 验收意见、新需求 |

#### 4.4 回顾会

| 项 | 说明 |
|------|------|
| 时间 | 评审会后 |
| 时长 | 1h |
| 参与者 | 团队全员（不含干系人） |
| 议程 | 1) 收集 3 件事：好的 / 改进的 / 行动 2) 投票 3) 制定 action |
| 输出 | 至少 1 个可落地改进项 |
| 记录 | 归档到 [迭代回顾记录](05-迭代回顾记录.md) |

#### 4.5 技术决策会

| 项 | 说明 |
|------|------|
| 时间 | 临时召集 |
| 时长 | ≤ 1h |
| 参与者 | 涉及模块负责人 + 架构师 |
| 议程 | 讨论技术方案、ADR |
| 输出 | 新增 / 更新 [ADR](../2.%20设计阶段/08-技术选型与决策记录（ADR）.md) |

### 5. 任务管理

#### 5.1 工具

- 研发一体化：PingCode / TAPD / Jira
- 看板视图：To Do → In Progress → Review → Done

#### 5.2 任务流转

```
Backlog → To Do → In Progress → Code Review → Testing → Done
                                                  ↓
                                              Reopen（Bug）
```

#### 5.3 任务拆分

- 单个任务 ≤ 2 天工作
- 跨人 / 跨模块必须拆细
- 必须含明确验收标准

### 6. 协作规范

#### 6.1 沟通

- 异步优先：文档、Issue、PR 评论
- 紧急同步：电话 / 钉钉
- 重要决策：会议 + ADR 记录
- **禁止**大段聊天记录作为决策依据

#### 6.2 文档先行

- 复杂需求先写 [PRD](../1.%20需求阶段/01-产品需求文档（PRD）.md)
- 技术方案先写 [ADR](../2.%20设计阶段/08-技术选型与决策记录（ADR）.md)
- API 变更先更新 [API 文档](../2.%20设计阶段/02-API设计文档.md)

#### 6.3 Code Review

- 详细见 [代码评审标准](../3.%20开发阶段/07-代码评审标准.md)
- 评审人 4h 内首次响应
- 紧急 PR 标记 `[URGENT]` 优先

#### 6.4 发布窗口

| 环境 | 发布窗口 |
|------|----------|
| dev | 任意 |
| test | 任意 |
| staging | 工作日 10:00-18:00 |
| prod | 周二 / 周四 14:00-16:00（高风险业务） |
| 紧急 | 全天，需 TL 审批 |

### 7. 远程协作

- 视频会议默认开摄像头
- 共享屏幕时静音通知
- 文档 / 决策必须有书面记录
- 时区差异：核心同步时间固定（如 10:00-12:00）
- 工具：钉钉 / 飞书 / Slack + 飞书表格 + GitLab

### 8. 度量

| 指标 | 计算 | 目标 |
|------|------|------|
| 迭代完成率 | 完成 Story / 计划 Story | ≥ 85% |
| 速度（Velocity） | 完成 Story Point 总和 | 趋势稳定 |
| 缺陷逃逸率 | 线上 Bug / 总 Bug | < 5% |
| 平均 PR 评审时长 | 评审时间 - 提交时间 | < 4h |
| 站会准时率 | 准时人数 / 团队人数 | ≥ 90% |
| 回顾会行动项完成率 | 完成 / 制定 | ≥ 80% |

### 9. 反模式（禁止）

- ❌ 跳过站会、评审会、回顾会
- ❌ 任务未拆分直接认领
- ❌ 阻塞超过 24h 未升级
- ❌ 决策只口头沟通，无书面记录
- ❌ 跨团队需求无接口人
- ❌ 回顾会流于吐槽，无 action
